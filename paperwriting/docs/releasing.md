# 发布清单

这是独立发布目录，不要重新混入原桌面工作目录。

- [ ] 检查 `.env.example` 只有空白 API 配置，真实 `.env` 不在暂存区。
- [ ] 确认没有 `data/`、`.cache/`、`.venv/`、备份、论文、模板或模型权重。
- [ ] 运行 `python -m pytest -q` 与 `python -m ruff check .`。
- [ ] 若自行加入截图，使用空白或合成数据，检查邮箱、论文和路径是否泄漏。
- [ ] 检查 `git status --short`、`git diff --cached --stat` 和完整暂存差异。
- [ ] 确认代码与素材来源，并选择项目级许可证。
- [ ] 在 GitHub 创建独立项目仓库（例如 PaperCoding），不是覆盖个人主页仓库。

首个版本应描述为本地工作台源码版，不宣称公共在线服务、已通过完整安全审计、模型质量提升百分比或大规模生产性能。

不包含旧评测数据的原因：它们依赖私人语料和本机证据 ID。今后若发布评测，应单独准备可公开语料、固定问题、标注和复现脚本，并披露模型、版本、费用、样本规模及失败结果。
